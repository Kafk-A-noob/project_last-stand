# 修正報告: Context Lost (OrbitControls Crash)

**日付:** 2026-02-13
**Status:** Fixed

## 1. 発生していた問題

モデルが存在しない（404 Not Found）ページに遷移した際、`THREE.WebGLRenderer: Context Lost` エラーが発生し、3Dキャンバス全体がフリーズ（再読み込みが必要な状態）していた。

## 2. 原因調査の結果

様々な要因を検証しました。

| 仮説                 | 検証内容                                                       | 結果                       |
| :------------------- | :------------------------------------------------------------- | :------------------------- |
| **手動リソース管理** | `ManualLoader` のインスタンス破棄処理が不完全？                | × 修正してもクラッシュ継続 |
| **HTML競合**         | `drei/Html` コンポーネントがDOM/Canvas競合を起こしている？     | × 排除してもクラッシュ継続 |
| **OrbitControls**    | **カメラ操作コンポーネントがアンマウント時に悪さをしている？** | **◎ 特定！**               |

### 判明した事実

`OrbitControls` はCanvasにイベントリスナーを登録していますが、エラー発生時などCanvasの状態が不安定なままアンマウントされると、WebGLコンテキストを巻き込んでクラッシュさせることが判明しました。

## 3. 実施した修正

### A. OrbitControls の安全化 (Main Fix)

`Scene.tsx` にて、**「モデルのロードが完了している時だけ OrbitControls を有効にする」** ように変更しました。

```tsx
// 変更後
{
  isLoaded && <OrbitControls makeDefault enablePan={false} />;
}
```

これにより、エラー画面（404）表示中は `OrbitControls` が存在しない状態となり、クラッシュが完全に回避されました。

### B. ローダーの安全性向上 (Sub Fix)

`ManualLoader.tsx` を、React Three Fiber 推奨の `useGLTF` フックを使用したモダンな記述に書き換えました。
旧来の手動Loaderよりもキャッシュ管理やメモリ解放が確実に行われます。

## 4. 最終確認

- `Radio` (404) への遷移でクラッシュせず、エラー画面が表示されることを確認。
- `ReactLogo` への復帰がスムーズに行えることを確認。
