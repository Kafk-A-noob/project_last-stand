# Portfolio Design Strategy: "Virtual Boutique"

「ターゲットとかアピールポイントとか分からん」という場合、**「面接で絶対に聞かれること」** を先に答えとして用意しておくカンニングペーパーだと思ってください。

## 1. Concept & Theme

**「誰に、何を、どう見せるか」**

* **Project Name:** `Virtual Boutique` (仮)
* **Concept:** **"Fabric on the Web"** (Web上で「布」を感じさせる)
* **Core Experience:**
* **Project Name:** `Virtual Boutique` (仮)
* **Concept:** **"Fabric on the Web"** (Web上で「布」を感じさせる)
* **Core Experience:**
  * ただモデルを回すだけでなく、**「リアルタイム3Dコンテンツのハイクオリティな衣装」** を、アプリ不要のブラウザで誰でも見れるようにする。
  * 既存のPortfolioによくある「重い、ロード長い、操作しづらい」を排除し、**「サクサク動くのにリッチ」** を目指す。

---

## 2. Target Audience (誰に売り込むか？)

**「このサイトを見た時、誰に『おっ、こいつ採用したい』と思ってほしいか」**

| ターゲット | 相手が求めていること | このポートフォリオでの回答 |
| :--- | :--- | :--- |
| **採用担当者**<br>(人事/PM) | 「実務で使えるか？」「学習能力はあるか？」 | 未経験ながら新しい技術(Next.js/R3F)をキャッチアップし、**「自分が作りたいものを形にする実装力」** があることを証明する。 |
| **テクニカル<br>ディレクター** | 「3Dの仕様を理解しているか？」<br>「最適化はできているか？」 | ポリゴン数削減、テクスチャ圧縮(WebP/ORM)、Draco圧縮など、**「Webで動かすための技術的最適化」** が完璧に行われている点を見せる。 |
| **エンジニア** | 「コードは読めるか？」 | コンポーネント設計、型定義、ディレクトリ構造など、**「保守性の高いコード」** を書いていることをアピールする。 |

> [!IMPORTANT]
> **戦略変更:** 「センス」や「美しさ」では勝負しません。
> **「3Dの技術的制約(重さ/形式)を理解し、エンジニアリングで解決できる能力」** を売りにします。

---

## 3. Appeal Points (強み・売り)

**「センスはない。だが、仕組みは知っている」**

1. **Pipeline Understanding (パイプラインへの理解):**
    * 「なぜ重いのか」「どうすれば軽くなるのか」を知っている。
    * モデラーとエンジニアの間に入り、データの橋渡しができる **「テクニカルアーティスト(TA)的な動き」** ができる。
2. **Implementation Power (実装力):**
    * 自分の欲しい機能を、調べながらでも実装しきる **「自走力」**。
    * 「リアルタイム3Dコンテンツでこれ欲しいな」→「じゃあWebで作るか」という動機で動けるエンジニア気質。
3. **Optimization Geek (最適化への執着):**
    * 見た目の派手さよりも、**「ロード時間の短縮」「FPSの安定」** に快感を覚えるタイプとして売り込む。

---

## 4. Key Features (機能要件)

**「このサイトで何ができるか？」**

* **Main Viewer:**
  * [x] 360度回転 (OrbitControls)
  * [ ] 自動ターンテーブルモード
* **Interaction:**
  * [ ] **Color/Texture Switcher:** ボタンを押すと服のカラーバリエーションが変わる。「素材の差し替え」ができることをアピール。
  * [ ] **Camera Work:** "Detail" ボタンを押すと、カメラが寄って（Zoom）、被写界深度（ボケ）がかかる等の演出。
* **Tech Showcase:**
  * [ ] **FPS Counter & Memory Monitor:** あえて画面端にパフォーマンス数値を出し、「負荷を気にしていますよ」とアピールする。

---

## 5. Technology Stack Selection (技術選定理由)

面接で「なぜこの技術を使ったの？」と聞かれた時の回答。

* **Next.js:** 高速な初期表示と、SEO（検索エンジン最適化）に強いため、ポートフォリオサイトとして最適。
* **React Three Fiber (R3F):** Three.jsを直接書くよりも、Reactのコンポーネント指向（再利用性）と相性が良く、状態管理（色変え等）が容易なため。
* **Tailwind CSS:** デザインの試行錯誤を高速化し、レスポンシブ対応（スマホ対応）を確実に行うため。
