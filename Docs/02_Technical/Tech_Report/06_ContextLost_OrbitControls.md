# 技術解説: Context Lost (OrbitControls Crash)

**作成日:** 2026-02-13
**対象:** 3D開発初心者向け

## 1. 問題の概要

「ユーザーがモデル読み込みエラー（404）を踏んだ瞬間、画面（Canvas）ごとフリーズする」という致命的なバグが発生しました。
このエラーメッセージ `THREE.WebGLRenderer: Context Lost` は、「GPUとの接続が切れた」ことを意味します。

## 2. 原因：OrbitControls の「お行儀の悪さ」

### 一見関係なさそうに見える犯人

当初、我々は「読み込み処理（Loader）」や「メモリ解放処理」を疑いましたが、真犯人はカメラを操作するための `OrbitControls` でした。
なぜカメラ操作がクラッシュを引き起こすのでしょうか？

### 理由

1. **イベントリスナーの登録:**
    OrbitControls は、マウス操作を検知するために `Canvas` 要素自体に「見張り番（イベントリスナー）」を配置します。

2. **不安定なアンマウント:**
    Reactでは、コンポーネントが消えるとき（アンマウント時）に「後片付け」をします。
    通常は問題ありませんが、「読み込みエラー」などで `Canvas` の内部状態が不安定になったタイミングで `OrbitControls` が後片付けをしようとすると、既に死にかけているGPUコンテキストに触れてしまい、**とどめを刺してしまう（Context Lost）** ことがあります。

## 3. 解決策：条件付きレンダリング

「モデルがちゃんと読み込まれて、画面が安定している時だけ OrbitControls を呼び出す」という安全策を取りました。

```tsx
{
  isLoaded && <OrbitControls />;
}
```

- **ロード中/エラー時:** `isLoaded` が false なので、OrbitControls は存在しません。怪我をする前に逃げている状態です。
- **成功時:** `isLoaded` が true になり、OrbitControls が登場します。

## 4. 教訓

React Three Fiber で謎のクラッシュ（Context Lost）が起きたら、まずは **「OrbitControls を一旦消してみる」** ことを試してください。
これが原因であることが非常に多いです。
