# Design Study: Footer Layout Alternatives

**Date:** 2026-02-09
**Subject:** ナビゲーション崩れの修正案比較 (UI/UX)

## 0. なぜ「横スクロール」を提案したのか？ (Reasoning)

**「3Dモデルの足元が見えなくなるのを防ぐため」** です。
スマホ等の縦長画面において、フッターが多段（折り返し）になって高さが増すと、肝心のMain Content (3Dモデル) の表示領域が圧迫されます。
InstagramのストーリーズやYouTubeのタグ一覧のように、横スクロールで高さを一定に保つのがモバイルファーストの定石です。

---

## 1. 案A: 横スクロール (Horizontal Scroll) [推奨]

現在の提案。

- **Unity:** `Scroll Rect` (Horizontal)
- **メリット:** 高さが固定され、3Dビューを邪魔しない。スワイプで直感的に探せる。
- **デメリット:** デスクトップでマウスホイール操作しにくい場合がある（Shift+Wheelが必要）。

## 2. 案B: 折り返し (Wrap)

ボタンが画面端に来たら次の行に送る。

- **Unity:** `Horizontal Layout Group` + `Wrap`
- **コード:** `flex-wrap`
- **メリット:** スクロール不要で全ボタンが見える（いずれ）。
- **デメリット:** ボタンが増えるとフッターが肥大化し、画面の半分以上を覆う可能性がある。

## 3. 案C: グリッドメニュー (Modal/Drawer)

「一覧を見る」ボタンを押し、別画面でリストを表示する。

- **Unity:** Button onClick -> `Panel.SetActive(true)`
- **メリット:** 100個以上のアイテムにも対応可能。画面がすっきりする。
- **デメリット:** ワンアクション増える（視聴体験が途切れる）。実装コストが高い（State管理、アニメーション）。

## 4. 案D: カルーセル (Carousel)

左右の矢印ボタン `<` `>` でスライドさせる。

- **Unity:** Page View / Snap Scroll
- **メリット:** 操作が明確。
- **デメリット:** 一覧性が低い。目的のアイテムまで何度もクリックが必要。

---

## 結論と提案 (Conclusion)

「手軽に見本盤をザッピングする」という体験においては、**案A（スクロール）** が最も適しています。
しかし、もし「一覧性」を重視するなら **案B（折り返し）** も選択肢に入ります。

どちらにしますか？

- **A:** スクロール（高さを守る）
- **B:** 折り返し（一覧性を守る）
- **C:** その他（実装コスト増）
