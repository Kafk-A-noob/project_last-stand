# Geminiへの質問プロンプト：3Dモデルのポリゴン数について

以下のテキストをコピーして、Gemini（またはChatGPTなど）に投げてください。
セカンドオピニオンとして、客観的な数値基準を確認できます。

---

## プロンプト (ここからコピー)

現在、Next.js + React Three Fiber (R3F) を使用して、ポートフォリオサイト(Project Last Stand)作成を進行しています。
表示モデル(方舟の積荷)として、画面中央に高品質な3Dモデル（ラジオ、カメラ、マグカップなどの小物）を1つずつ表示し、ユーザーが自由に回転させて鑑賞できる機能を実装しています。

**【質問】**
この用途において、1つの3Dモデルあたりのポリゴン数（三角面数/Tris）の目安として「15,000 Tris」というターゲットが他AIにより提示されました。これは適切でしょうか？

**【前提条件】**

1. **ターゲットデバイス:** PCおよび最新のスマートフォン（iPhone 13以降など）。
2. **表示数:** 画面内に表示されるモデルは常に「1体」のみ（背景はシンプル）。
3. **パフォーマンス:** 60fpsを維持しつつ、見た目のクオリティ（シルエットの滑らかさ）を重視したい。
4. **テクスチャ:** 2K (2048x2048) 程度のPBRテクスチャを使用予定。
5. **現在のプラン:** Blenderでハイポリゴンを作成後、リトポロジーまたはデシメートで削減し、Draco圧縮をかけてGLB出力する予定。

**【回答してほしいこと】**

1. 15,000 Tris という数値は、Web 3Dにおいて「安全圏」か「重すぎる」か？
2. モバイル端末での許容範囲（ドローコールや頂点数の限界）はどの程度か？
3. もし余裕があるなら、どこまでリッチにして良いか（例えば30,000 Trisまで上げても実用上問題ないか）？
4. 根拠となるベンチマークや、Sketchfab/Unity WebGL等の推奨仕様があれば教えてください。
