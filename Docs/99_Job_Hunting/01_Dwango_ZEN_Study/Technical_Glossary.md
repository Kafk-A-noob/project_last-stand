# 面接対策：技術用語集 (Technical Glossary)

**目的:** 「この程度の用語は知ってるよね？」という前提で質問された時に、慌てず「あぁ、〇〇のことですね」と返すための用語集です。
**使い方:** 暗記する必要はありません。「自分のポートフォリオのどこで使われているか」をイメージできればOKです。

---

## 1. Next.js / React 関連

| 用語                             | 意味・解説                                                                               | ポートフォリオでの実例                                                                |
| :------------------------------- | :--------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------ |
| **SSR (Server Side Rendering)**  | サーバー側でHTMLを作ってからブラウザに送る仕組み。初期表示が速く、SEOに強い。            | 今回は `layout.tsx` などのガワ部分で使用。                                            |
| **CSR (Client Side Rendering)**  | ブラウザ側でJavaScriptが動いて画面を作る仕組み。3Dや複雑なUIはこっち。                   | `ViewCanvas` (3D部分) は `use client` を付けてCSRにしています。                       |
| **Hydration (ハイドレーション)** | サーバーから送られてきた乾いたHTMLに、後からJSが「水(機能)」を与えて動くようにすること。 | 画面が表示された直後にボタンが押せるようになる瞬間。これが遅いと「TBT」が悪化します。 |
| **Props (プロップス)**           | 親コンポーネントから子コンポーネントに渡す引数（データ）。バケツリレー。                 | `ManualLoader` に `path={model.path}` を渡している部分など。                          |
| **Hooks (フック)**               | `use` で始まるReactの機能。クラスを書かなくても状態管理などを行える魔法。                | `useEffect` (ロード時実行), `useState` (状態), `useStore` (Zustand)                   |
| **Dependency Array (依存配列)**  | `useEffect` などの第二引数 `[]`。ここに書いた値が変わった時だけ再実行される。            | `useEffect(..., [path])` -> パスが変わった時だけモデルをロードする。                  |
| **Wrapper (ラッパー)**           | 何かを包んで機能を追加するコンポーネント。                                               | `ViewCanvas` は `Canvas` を包んでエラーハンドリング等の機能を持たせたラッパーです。   |

## 2. 3D / R3F (React Three Fiber) 関連

| 用語                            | 意味・解説                                                                                   | ポートフォリオでの実例                                                      |
| :------------------------------ | :------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------- |
| **Canvas (キャンバス)**         | 3Dを描画するための画用紙(HTML要素)。WebGLの描画領域。                                        | `ViewCanvas.tsx` にある `<Canvas>` タグ。                                   |
| **Mesh (メッシュ)**             | 3Dオブジェクトの実体。「ジオメトリ(形)」と「マテリアル(色・質感)」のセット。                 | Blenderで作ったモデルはUnityでいうGameObject、R3FではMeshとして扱われます。 |
| **Geometry (ジオメトリ)**       | 形状データ。頂点(Vertex)の集まり。                                                           | `boxGeometry` (立方体) や `gltf.scene` の中の形状データ。                   |
| **Material (マテリアル)**       | 表面の質感設定。色、反射率、テクスチャなど。                                                 | `MeshStandardMaterial` など。Blenderで設定した色がこれ。                    |
| **GLTF / GLB**                  | 「3DのJPEG」と呼ばれる、Web向けの軽量3Dフォーマット。GLBはバイナリ版（一つにまとまった奴）。 | 今回のアセット (`radio.glb` など) は全てこれ。                              |
| **Draco Compression**           | Googleが開発した3Dデータの圧縮技術。解凍に少し時間がかかるが、ファイルサイズが激減する。     | `ManualLoader` で `draco` 設定をしているのはこれを使えるようにするため。    |
| **Frame Loop (フレームループ)** | 1秒間に60回(60FPS)実行される描画ループ。Unityの `Update()`。                                 | R3Fでは `useFrame` フックを使うとここに処理を書ける。                       |

## 3. 状態管理・アーキテクチャ関連

| 用語                           | 意味・解説                                                                     | ポートフォリオでの実例                                                                   |
| :----------------------------- | :----------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------- |
| **State (ステート)**           | アプリの状態。変数のことだが、書き換わると画面が再描画されるのが特徴。         | `currentModel` (今のモデル) や `isLoaded` (ロード中か？)。                               |
| **Store (ストア)**             | ステートをまとめて管理する場所。銀行のようなもの。                             | `store.ts` がまさにこれ。Zustandで作った貯蔵庫。                                         |
| **Action (アクション)**        | ストアの中身を書き換えるための関数。                                           | `goToNext()`, `setModelData()` など。                                                    |
| **Immutable (イミュータブル)** | 「不変」。既存のデータを直接書き換えずに、新しいデータをコピーして作ること。   | 配列に `push` せず `[...prev, new]` と書くとか、`set({...state, key: val})` と書く作法。 |
| **Single Source of Truth**     | 「信頼できる唯一の情報源」。データは一箇所だけで管理し、コピーを作らない原則。 | 今回は `asset-manifest.ts` を静的データの正解とし、Storeはそれを参照するだけにしました。 |

## 4. その他・開発環境

| 用語                             | 意味・解説                                                                   | ポートフォリオでの実例                                                         |
| :------------------------------- | :--------------------------------------------------------------------------- | :----------------------------------------------------------------------------- |
| **Lint / Linter (リント)**       | コードの自動チェックツール。文法ミスや「使ってない変数」を怒ってくれる。     | `npm run lint` で実行。ESLintのこと。                                          |
| **Type Safe (型安全)**           | TypeScriptなどで「数値の場所に文字列を入れられない」ように守られている状態。 | `interface ArchiveItem` で型定義しているおかげで、ちぐはぐなデータが入らない。 |
| **Bundle Size (バンドルサイズ)** | ブラウザに送られるJSファイルの容量。小さいほど読み込みが速い。               | Tailwind採用でこれを減らしました。                                             |
| **CI/CD**                        | 継続的インテグレーション/デリバリー。テストやデプロイを自動化すること。      | GitHub Actionsで自動ビルドしている仕組みのこと。                               |
| **Zero Runtime**                 | 実行時(ブラウザ)に余計なJS計算をしないこと。パフォーマンスが良い。           | Tailwind CSSの強み。                                                           |

---

これらの単語が出たら、**「あー、〇〇の時に使ったアレだな」** と脳内でリンクさせてください。
細かい定義より、「自分のコードのどこか」を指差せることの方が重要です。
