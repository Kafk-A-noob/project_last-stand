## 2. アピール戦略 (Strategy)

### 軸1: 「ユーザー体験(UX)」への執着を語る

ZEN Studyは「学習を継続させるためのUX」を重視しています。
**Project Last-Stand** で実装した **「Optimistic UI (楽観的UI更新)」** は、まさにこの文脈で刺さります。

- **アピールトーク:**
  「3Dポートフォリオにおいて、モデルのロード待ち時間はユーザーの離脱要因になります。そこで、『ユーザーの操作に対して即レスポンスを返す（楽観的UI）』ことを優先し、裏側でロード処理を行う設計にしました。この『ユーザーを待たせない工夫』は、学習アプリのUXにも通じると考えています。」

### 軸2: 「技術的探究心」と「基礎力」

R3F (Three.js) という、通常のWeb開発よりもパフォーマンス制約が厳しい環境で開発した経験は、「Webの基礎（レンダリング、メモリ管理）」への深い理解を証明します。

- **アピールトーク:**
  「VRChat環境下でのUnityの経験をベースにしつつ、Web標準技術(DOM)とWebGL(Canvas)の役割分担を明確に設計しました。特に、重い処理(3D)と軽い処理(UI)の状態管理を分離する『Hybrid State Management』により、メインスレッドのブロックを防いでいます。」

### 軸3: 未経験からの「自走力」

UnityからWebへ転向し、短期間でNext.js App Routerを習得した学習能力は、ドワンゴが求める「自発的に行動できる」人物像に合致します。

## 2.5 懸念点の払拭 (Handling the Gap)

### 「実務経験3年」に対する戦略

正直に「学習期間は短い」と認めつつ、「学習密度の濃さ」で勝負します。
通常の3年間でも触れないような **「3D × Web × Optimistic UI」** という複合領域を、設計からデプロイまで一人で完遂した実績は、未経験ながら「エンジニアリング全体の地図」を持っていることの証明です。

### 「AI (Gemini) の利用」に対するスタンス

**「AIに全部書いてもらった」ではなく、「AIを『専属のメンター(家庭教師)』として使い倒し、学習速度を最大化した」というスタンスを取ってください。**

- **Bad:** 「AIに聞いたら動きました（中身は理解していません）」
- **Good:** 「独学では理解に時間がかかる概念（Optimistic UIやState管理）を、AIに解説させながら実装しました。**『なぜこのコードなのか』『なぜエラーが出たのか』を一行一行AIと議論することで、その時点で考えうるベストプラクティスを短期間で吸収しました。**」

## 3. 想定質問と回答案 (Mock Q&A)

### Q1. なぜ Tailwind CSS を選んだのですか？ (ドワンゴは CSS-in-JS 採用)

**A.**
「本ポートフォリオは『開発速度』と『学習コストの最小化』を優先し、直感的に書ける Tailwind CSS を採用しました。
ゼロランタイムによる軽量化も魅力でしたが、何より React と 3D (R3F) の学習に集中したかったため、スタイリングの悩み時間を減らしたかったのが本音です。

ドワンゴ様が採用されている Panda CSS や Styled Components は未経験ですが、大規模開発における『保守性』や『カプセル化』のために重要だと理解しています。
入社後はチームの設計思想を学び、Tailwind との違いを吸収しながら、プロジェクトの標準技術を１日でも早く使いこなせるよう努めます。」

> **[補足: 素直な戦略]**
> 「技術選定できる」と嘘をつくより、「なぜTailwindで楽をしたか」を認めつつ、「新しい技術(CSS-in-JS)を学ぶ意欲がある」と伝える方が好印象です。ジュニアに求められるのは「完璧な知識」ではなく「吸収力」です。

### Q2. 苦労した技術的課題は？

**A.**
「開発環境(ローカル)では快適だったのに、本番環境(Vercel)にデプロイした途端、3Dモデルのロード待ちでエラー画面になり、一覧メニューからも操作不能になる問題に直面しました。
調査の結果、ネットワーク遅延を考慮しない設計が原因だと判明しました。そこで、『Optimistic UI』というパターンを学び、ロード完了を待たずに次の画面情報を先行表示するようにコードを書き換えました。
**『ローカルで動けばOKではない』** というWebアプリ開発の難しさと面白さを、このバグ修正を通じて学びました。」

### Q3. テストコード(Vitest)の経験は？

**A.**
「正直なところ、テストコードをバリバリ書く経験までは積めていません。
ただ、『CI/CDパイプラインの中でテストが自動実行される環境』自体は、モダン開発の標準だと理解し、GitHub Actions上でVitestが動く構成だけは構築しました。
現在は最低限の動作確認レベルですが、入社後は先輩方のレビューを受けながら、保守性の高いテストコードの書き方を吸収していきたいです。」

### Q4. 実務未経験ですが、3年以上の要件をどう捉えていますか？ [重要]

**A.**
「確かに実務経験はありませんし、チーム開発の作法も未熟です。
しかし、このポートフォリオ制作において、単にコードを書くだけでなく**『企画・要件定義・デプロイ・運用・バグ修正』** というWeb開発の工程を、モダンな技術スタック（Next.js App Router）を用いてAIの補佐もありつつ一周回しました。
『全体像を知った上で、自分の未熟さを自覚している』という点においては、実務の中で成長できると確信しています。」

### Q5. このコードは本当に自分で書いたのですか？（AI利用について）

**A.**
「はい、設計と最終的なコード内容の把握は全て自分で行っていますが、学習の補助輪としてAI(Gemini)とIDEエディタ(Antigravity)をフル活用しました。
特に、Next.jsの最新機能やエラー解決においては、AIを**『24時間質問できるメンター』**として使い、『なぜこう書くのか？』を徹底的に質問攻めにしました。
AIに使われるのではなく、AIを使い倒して『本来なら3年かかる学習を半年で圧縮する』つもりで取り組んできました。」
